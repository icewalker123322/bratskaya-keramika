# Проверки реализации

## Актуальный расширенный аудит — 11 ноября 2026

Заключительный прогон выполнен непосредственно по https://icewalker123322.github.io/bratskaya-keramika/: все 40 браузерных проверок прошли, включая реальный вход/выход, CRUD скрытого FAQ, загрузку/удаление фото через опубликованную админку. Публикация технических изменений `01e6576ae138cadad801d40ee0d63a7ceaffe76e` подтверждена успешным GitHub Pages workflow. По завершении в БД 96 исходных записей, тестовых записей и объектов Storage нет.

VK, Telegram и Яндекс Карты ответили HTTP 200. MAX ответил HTTP 403 автоматическому GET: действительность приглашения не подтверждена, нужна ручная проверка. GPS-метки EXIF в 10 исходных JPG/PNG не обнаружены. Браузерная проверка декодирует изображения с ожиданием ленивой загрузки, а не считает ещё не загруженное изображение сломанным.

Итог локального прогона `qa-browser.mjs --auth`: 40 PASS, включая полный цикл сохранения/удаления скрытого FAQ и загрузки фотографии через input устройства/удаления через интерфейс с настоящим Supabase. Исходное состояние после тестов восстановлено. Performance advisors обнаружил дублирующие SELECT-политики; они объединены миграцией `combine_content_select_policies`, доступ anon и обычного authenticated остаётся только к опубликованным записям. Для существующих установок добавлен `supabase/hardening.sql`.

Браузер Chrome проверил реальное чтение Supabase, отсутствие загрузки esm.sh/SDK авторизации на публичной странице, отсутствие cookies/sessionStorage приложения на публичной странице в чистом профиле, загрузку фото, фильтры, галерею до/после замены DOM, экранирование HTML, мобильное меню и реальный вход/выход через интерфейс. Обзор, страницы, фото и настройки проверены на ширинах 360, 390, 768, 1440 px без горизонтальной прокрутки. Открытие настоящей формы редактирования проверено.

`qa-auth.mjs --storage` прошёл на подключённом проекте: реальный вход/выход, права владельца, публичные 96 записей, запрет anon-записи, создание/сохранение/удаление скрытого элемента, отсутствие скрытого элемента в публичном API, запрет anon-загрузки фото, загрузка JPG владельцем, сохранение ссылки на фото, публичное чтение файла, блокировка удаления используемого фото и успешное удаление неиспользуемого, серверный запрет неподходящего MIME и файла > 5 МБ. Тестовые данные удалены. Дополнительно SQL-транзакциями с rollback проверены RPC перестановки туда/обратно и запреты записи обычному authenticated без членства администратора.

Bucket `site-images` создан владельцем через консоль, подтверждены public=true, лимит 5 242 880 байт и MIME JPG/PNG/WebP. Первоначальная проблема отсутствующего хранилища закрыта. Один первоначальный HTTP-тест был исправлен: для DELETE тестовый Node-клиент должен отправлять Content-Length, а пустые запросы не должны объявлять JSON-тело; это была ошибка тестового клиента, а не Storage SDK сайта.

Проверка локальных путей index.html и admin/index.html не нашла отсутствующих ресурсов. На публичной странице один h1, все изображения имеют alt, форм посетителей нет. Админка имеет отдельные h1 для двух взаимоисключающих экранов.

Исправления: анонимное чтение публичного контента без SDK/сессии, credentials=omit и no-referrer, таймаут, CSP meta для скриптов/объектов/форм, no-referrer в HTML, canonical/sitemap, защита от закрытия формы во время операции, обработка отсутствующего bucket. Полноценные HTTP frame-ancestors и управление журналами требуют соответствующего хостинга; meta CSP этого не заменяет.

Security advisors обнаружил предупреждение об отключённой проверке скомпрометированных паролей. Настройка выполняется владельцем в Auth; см. [Supabase Password Security](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection). Текущий пароль был передан через чат и перед передачей проекта должен быть заменён клиентом на уникальный. Пароль не записан в исходники.

Юридическая готовность не подтверждена: нет реквизитов исполнителя и утверждённой карты обработки данных; Supabase расположен вне РФ. Подробный отчёт находится локально в LEGAL_AUDIT_RU.md и не публикуется вместе с сайтом. Отсутствие формы и аналитики не доказывает отсутствие обработки ПД в журналах или мессенджерах.

Ниже сохранена история предыдущих проверок. Её первоначальные ограничения по bucket, входу, сохранению и RPC следует читать с учётом актуального результата выше.
